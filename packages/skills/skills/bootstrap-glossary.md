# glossary 生成任务(pinery bootstrap)

对当前仓库做一次结构化扫描,生成术语表**草稿**供工程师 review。目标读者是之后回答业务问题的调查 agent。

## 扫描顺序

1. 根目录与一级目录结构(`ls`、`tree -L 2`)
2. README 与 docs/ 下的说明文档
3. 包清单(package.json / go.mod / pyproject.toml / pom.xml …)的名称、脚本、依赖线索
4. 路由/入口文件、领域模型目录(model/entity/domain/schema 命名的目录)
5. 配置文件中的业务开关与阈值

## 输出要求

严格按 `.pinery/glossary.md` 模板的四个小节输出完整 markdown:

- **业务概念 → 代码映射**:从路由、模型、任务名中提炼 10-25 个业务术语,每个给出一句话含义 + 代码位置。
- **模块地图**:一级目录逐个一句话职责。
- **领域约定**:能从代码中确认的跨模块约定(不确定就不写)。
- **已知坑位**:明显的废弃目录、重复实现、TODO 密集区。

规则:每条映射必须有真实路径背书,禁止臆测;拿不准的条目末尾标 `(待确认)`。
直接输出 markdown 全文,不要输出扫描过程。
