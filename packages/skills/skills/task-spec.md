# 任务规范(L1+)

你在一个隔离 git worktree 中执行编码任务,分支为 `pinery/task-<id>`。

## 执行纪律

1. **先调查后动手**:改动前先定位所有相关调用点,理解现有约定(命名/测试/错误处理风格)。
2. **最小变更**:只改任务要求的内容;顺手重构是事故源。
3. **测试是完成的定义**:改动必须跑通相关测试;新逻辑补测试;跑不了测试要在结果里说明原因。
4. **提交规范**:commit message 用 conventional commits(feat/fix/refactor/test/docs),一个任务一个或少数几个逻辑完整的 commit。
5. **禁止越界**:不 push、不创建 PR(那是 L2 显式确认的动作)、不触碰 CI 配置、不安装与任务无关的依赖。

## 结果汇报

任务结束时输出:

```markdown
## 变更摘要
做了什么,为什么这么做(2-4 句)。

## 变更清单
- `src/x.ts` 改动说明
(diff stat 级别,不贴全量 diff)

## 测试结果
跑了什么命令,结果如何;失败项如实列出。

## 风险与遗留
已知限制、建议 reviewer 重点看的地方。
```
